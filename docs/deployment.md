# Deployment guide

How each CareConnect client is built for production, where the builds go, and how to check a deployment worked. The current builds are on the [v1.1.0 release](https://github.com/viclee1/careconnect-swen661/releases/tag/v1.1.0); the web app is live at <https://careconnect-swen661.vercel.app>.

| Platform | Client | Output | Where it is published |
|:--|:--|:--|:--|
| Web / PWA | React + Vite (`/`) | `dist/` | Vercel, from `main` |
| Android | Flutter (`flutter/`) | `.apk`, `.aab` | GitHub release; APK also in `apk-submission/` |
| iOS | Flutter (`flutter/`) | unsigned `.ipa` | GitHub release |
| Android | React Native + Expo (`mobile/`) | `.apk`, `.aab` | GitHub release; APK also in `apk-submission/` |
| iOS | React Native + Expo (`mobile/`) | unsigned `.ipa` | GitHub release |
| Windows, macOS, Linux | Electron (`desktop/`) | `.exe`, `.dmg`, `.AppImage`, `.deb` | GitHub release; every CI run's `package` job |

None of the clients needs a server or secret: they run on mock data stored on the device (see [API reference](api.md)).

## Web — Vercel

**Build.**

```bash
npm ci
npm run build          # type-checks, then writes dist/ with the service worker and manifest
npm run preview        # serves dist/ on :4173, the same build the e2e tests use
```

**Deploy.** The Vercel project is connected to the GitHub repository: every push to `main` deploys to production, and every pull request gets a preview URL posted as a check. Vercel runs `npm run build` and serves `dist/`. Nothing needs to be set in Vercel's environment; `VITE_*` variables in `.env.example` are optional.

[`vercel.json`](../vercel.json) does three things the PWA depends on:

- Rewrites any path that is not a real file to `/index.html`, so `/app` (the manifest's `start_url`) and deep links like `/app/medicines` load on a cold visit instead of returning 404.
- Serves `sw.js` with `Cache-Control: no-cache`, so a new deploy's service worker is picked up on the next visit.
- Serves `manifest.webmanifest` as `application/manifest+json`.

To host elsewhere (Netlify, any static host), deploy `dist/` and reproduce those three rules.

**Check it.**

```bash
curl -s -o /dev/null -w "%{http_code}\n" https://careconnect-swen661.vercel.app/app/medicines   # 200
curl -s https://careconnect-swen661.vercel.app/manifest.webmanifest | head -5                    # the manifest JSON
node scripts/verify-pwa.mjs        # installability checks; needs `npm run preview` running (or BASE_URL set)
```

Then open the site in Chrome or Edge and confirm the install icon appears in the address bar, or use **Share → Add to Home Screen** in Safari on iOS.

## Flutter — Android and iOS

Prerequisites: Flutter SDK (3.47.1 in CI), Android Studio with an SDK, and Xcode for iOS. Run `flutter doctor` first.

**Android.**

```bash
cd flutter
flutter pub get
flutter build apk --release          # build/app/outputs/flutter-apk/app-release.apk
flutter build appbundle --release    # build/app/outputs/bundle/release/app-release.aab
```

The release build is signed with the debug key (`android/app/build.gradle.kts`, `signingConfig = signingConfigs.getByName("debug")`). That is enough to sideload the APK, which is how the course installs it. To publish to Google Play, create an upload keystore, add a `release` signing config that reads it from `key.properties` (kept out of git), and change the application ID from `com.example.careconnect_mobile`, which Play rejects.

**iOS (unsigned).**

```bash
flutter build ios --release --no-codesign
mkdir -p Payload && cp -R build/ios/iphoneos/Runner.app Payload/
zip -qr CareConnect-Flutter-unsigned.ipa Payload && rm -r Payload
```

An unsigned IPA cannot be installed as-is; re-sign it with a development certificate and provisioning profile (Xcode, or a tool such as `ios-app-signer`). For TestFlight or the App Store, open `ios/Runner.xcworkspace`, set a team and bundle identifier, and use **Product → Archive**.

**Check it.** `adb install -r build/app/outputs/flutter-apk/app-release.apk`, launch CareConnect, sign in, and open each tab.

## React Native (Expo) — Android and iOS

Prerequisites: Node 22, JDK **17 or 21** (Gradle's native build fails on JDK 25/26 — see the [mobile README](../mobile/README.md#building-for-android-locally-for-maestro-or-a-debug-apk-without-eas)), Android SDK, and Xcode for iOS. `android/` and `ios/` are generated by Expo and not committed.

**With EAS (Expo's cloud build).** Profiles are in [`mobile/eas.json`](../mobile/eas.json).

```bash
cd mobile
npm ci
npm install -g eas-cli && eas login
eas build --platform android --profile preview      # installable .apk
eas build --platform android --profile production   # .aab for Google Play
eas build --platform ios                             # needs an Apple developer account
```

**Locally (how the v1.1.0 builds were made).**

```bash
cd mobile
npm ci
npx expo prebuild --platform android
cd android
./gradlew assembleRelease     # app/build/outputs/apk/release/app-release.apk
./gradlew bundleRelease       # app/build/outputs/bundle/release/app-release.aab
```

Expo's generated release config signs with the debug keystore, as with Flutter. For iOS:

```bash
npx expo prebuild --platform ios
cd ios && pod install && cd ..
xcodebuild -workspace ios/CareConnect.xcworkspace -scheme CareConnect \
  -configuration Release -sdk iphoneos -derivedDataPath build CODE_SIGNING_ALLOWED=NO
mkdir -p Payload && cp -R build/Build/Products/Release-iphoneos/CareConnect.app Payload/
zip -qr CareConnect-ReactNative-unsigned.ipa Payload && rm -r Payload
```

The app ID on both platforms is `edu.umgc.swen661.careconnect` (`mobile/app.json`).

**Check it.** `adb install -r android/app/build/outputs/apk/release/app-release.apk`, then run the Maestro flows in `mobile/maestro/` against the installed build.

## Electron — Windows, macOS, Linux

```bash
cd desktop
npm ci
npm run package:win      # release/CareConnect-Setup-1.0.0.exe   (NSIS, x64)
npm run package:mac      # release/CareConnect-1.0.0-arm64.dmg
npm run package:linux    # release/: an .AppImage and a .deb
```

Each script runs `npm run build` first, then `electron-builder` with [`electron-builder.yml`](../desktop/electron-builder.yml); icons come from [`desktop/build/`](../desktop/build/README.md). Build each installer on its own OS where you can — the `package` job in [`desktop-tests.yml`](../.github/workflows/desktop-tests.yml) does exactly that on Windows, macOS and Linux runners and uploads the installers as artifacts, so a member without a given OS downloads them from the latest CI run.

The installers are unsigned. Windows SmartScreen shows **More info → Run anyway**; macOS needs right-click → **Open** on first launch. Signing needs an Authenticode certificate (Windows) and an Apple Developer ID plus notarization (macOS), configured through `electron-builder`'s `win.certificateFile` and `mac.notarize` options.

**Check it.** Install, launch, and follow [`docs/desktop-accessibility-test.md`](desktop-accessibility-test.md) — it is written against the installed build.

## Publishing a release

1. Bump versions where they changed: `mobile/app.json` (`expo.version`), `flutter/pubspec.yaml` (`version`), `desktop/package.json`.
2. Build every artifact above and give them the release names: `CareConnect-Flutter-release.apk`, `CareConnect-Flutter-release.aab`, `CareConnect-Flutter-unsigned.ipa`, `CareConnect-ReactNative-release.apk`, `CareConnect-ReactNative-release.aab`, `CareConnect-ReactNative-unsigned.ipa`, and the Electron installers as built.
3. Copy the two APKs into `apk-submission/` and commit them (they are under GitHub's 100 MB limit; the AABs, IPAs and installers are not committed).
4. Write checksums and publish:

   ```bash
   shasum -a 256 CareConnect-* > SHA256SUMS.txt
   gh release create v1.2.0 CareConnect-* SHA256SUMS.txt \
     --repo viclee1/careconnect-swen661 --title "CareConnect 1.2.0 — production builds" --notes-file notes.md
   ```

5. Merge to `main` so Vercel deploys the matching web build, then run the web checks above.
